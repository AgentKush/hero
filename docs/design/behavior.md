# Warden Runtime Behavioural Detection Set (usermode C#/.NET 10, no ETW-kernel, no NuGet)

> Area: `runtime-heuristics` · adversarial critique verdict: **needs_rework**

## Summary
Warden's runtime engine is a per-process rolling risk score fed by ~40 independent detections drawn from six telemetry planes: process/lineage snapshots (Toolhelp32 + NtQueryInformationProcess), per-PID socket tables (GetExtendedTcpTable/UdpTable + TCP ESTATS byte counters), file provenance (WinVerifyTrust, PE parsing, entropy, ADS), handle-table enumeration (NtQuerySystemInformation SystemExtendedHandleInformation), remote-memory inspection (VirtualQueryEx/EnumProcessModules), and the Windows event logs. Verified on this machine: Sysmon is NOT installed, ProcessCreationIncludeCmdLine is not set and auditpol is unreadable unelevated (so Security 4688 must be treated as absent), PowerShell ScriptBlockLogging policy is off (4104 still fires for auto-flagged suspicious blocks), the Defender Operational log is present and readable with 9309 records, GPU Engine perf counters expose per-PID engtype_Compute instances, Get-DnsClientCache works unelevated, and Get-MpPreference exclusions require elevation. Scores are additive with a 30-minute half-life decay, and no auto-kill fires on a single signal: an autonomous action requires a HIGH-tier anchor detection plus a corroborating detection from a different family plus a protected-process/publisher-allowlist veto pass. Every detection carries explicit false-positive suppressors tuned to a developer host running Node, Python, Rust, Unreal, Blender, BlueStacks-with-root, local dev servers and long CPU-saturating slot-math simulations. Precision is enforced structurally: a 7-day learning mode, publisher and path allowlists, minimum sample counts before any statistical detection may alert, and hard caps on how much any single family can contribute to the total score.

## Items (55)
### [critical] T01 Process snapshot plane (identity, lineage, command line)
TIER: infra | SCORE: n/a | CADENCE: 2s. Foundation for every lineage and command-line detection. Every process gets a stable key of PID + creation FILETIME so PID reuse can never mis-attribute a detection, and lineage is resolved against that key, not against a bare PPID.

**How:** CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS)/Process32FirstW/NextW for pid, ppid, exe name. Open with PROCESS_QUERY_LIMITED_INFORMATION and call QueryFullProcessImageNameW (dwFlags=0) for the true path, GetProcessTimes for creation FILETIME, IsWow64Process2, GetProcessInformation for the rest. Command line: NtQueryInformationProcess(ProcessBasicInformation) to get PebBaseAddress, ReadProcessMemory the PEB -> RTL_USER_PROCESS_PARAMETERS -> CommandLine UNICODE_STRING (use the 64-bit PEB; for WOW64 targets use ProcessWow64Information). Fallback when the read fails (protected/elevated targets): a single batched WMI query 'SELECT ProcessId,ParentProcessId,CommandLine,CreationDate,ExecutablePath FROM Win32_Process' via System.Management, cached 10s. Session/user: ProcessIdToSessionId + OpenProcessToken(TOKEN_QUERY) + GetTokenInformation(TokenUser/TokenIntegrityLevel/TokenElevation). Window titles: EnumWindows + GetWindowThreadProcessId + GetWindowTextW + IsWindowVisible.

**False positives:** Unelevated Warden cannot read the PEB of elevated or protected processes; record 'cmdline unavailable' as a distinct state and never treat missing command line as suspicious. Run Warden elevated (manifest requestedExecutionLevel=requireAdministrator) or the credential-access and memory families degrade badly.

### [critical] T02 Per-PID socket plane with byte counters
TIER: infra | SCORE: n/a | CADENCE: 5s adaptive (1s while a process is on the watchlist). Produces the connection-event stream that all network detections consume, plus per-connection byte volumes, which is the single highest-value telemetry most usermode tools skip.

**How:** GetExtendedTcpTable(TCP_TABLE_OWNER_PID_ALL, AF_INET and AF_INET6) and GetExtendedUdpTable(UDP_TABLE_OWNER_PID). Diff consecutive snapshots keyed on (localAddr,localPort,remoteAddr,remotePort,pid,creationTime) to synthesise CONNECT / CLOSE / LISTEN events with timestamps. Byte volume: SetPerTcpConnectionEStats(TCP_ESTATS_DATA_RW_v0{EnableCollection=TRUE}) once per new connection, then GetPerTcpConnectionEStats(TcpConnectionEstatsData) -> TCP_ESTATS_DATA_ROD_v0.DataBytesOut/DataBytesIn (iphlpapi.dll, requires admin; degrade gracefully). Enrich remote IPs from the DNS cache via DnsGetCacheDataTable (dnsapi.dll, undocumented) with a fallback to parsing 'powershell -NoProfile -Command Get-DnsClientCache | ConvertTo-Json' every 30s — verified working unelevated, 18 entries on this host.

**False positives:** A 5s poll cannot see connections shorter than the poll interval; never conclude 'no network activity' from an empty diff. Loopback (127.0.0.0/8, ::1), link-local, RFC1918 and the BlueStacks/Hyper-V vEthernet ranges must be classified separately from real egress — this host will have constant loopback traffic from dev servers and the Unreal/Blender licence and asset services.

### [critical] T03 Authenticode / provenance plane with caching
TIER: infra | SCORE: n/a. Signature state is the strongest single precision multiplier in the whole system; almost every scored detection is gated on it. Results are cached keyed on (path, size, lastWriteUtc, SHA-256 of first+last 64KB) so a full verify runs once per binary.

**How:** WinVerifyTrust(NULL, WINTRUST_ACTION_GENERIC_VERIFY_V2, WINTRUST_DATA{dwUIChoice=WTD_UI_NONE, fdwRevocationChecks=WTD_REVOKE_NONE for speed then WTD_REVOKE_WHOLECHAIN on demand, dwStateAction=WTD_STATEACTION_VERIFY, dwProvFlags=WTD_SAFER_FLAG|WTD_CACHE_ONLY_URL_RETRIEVAL}). Distinguish the return codes: 0=valid, TRUST_E_NOSIGNATURE(0x800B0100)=unsigned, TRUST_E_BAD_DIGEST(0x80096010)=tampered, CERT_E_EXPIRED, CERT_E_REVOKED, CERT_E_UNTRUSTEDROOT. For catalog-signed OS files, first try CryptCATAdminAcquireContext2/CryptCATAdminCalcHashFromFileHandle/CryptCATAdminEnumCatalogFromHash. Signer identity via X509Certificate.CreateFromSignedFile(path).Subject, plus the countersigned timestamp. Also read the Zone.Identifier ADS (CreateFileW on "path:Zone.Identifier:$DATA") for ZoneId=3 and HostUrl/ReferrerUrl.

**False positives:** Rust/cargo, Node native modules, Python venv shims, MSVC build outputs and the user's own Unreal/Blender/slot-math builds are ALL legitimately unsigned and live under D:\My projects — unsigned alone must never score above 'context'. Maintain a per-machine publisher allowlist (Microsoft, NVIDIA, Epic Games, Blender Foundation, Valve, Python Software Foundation, OpenJS, Docker, JetBrains, Google) plus a user-managed 'my build outputs' path allowlist seeded from directories containing a .git, Cargo.toml, package.json, .uproject or .sln.

### [critical] T04 Handle-table plane (the usermode substitute for kernel ETW)
TIER: infra | SCORE: n/a | CADENCE: 15s, plus on-demand when a process crosses 40 points. This one plane delivers lsass access, browser-credential access, DPAPI blob access and wallet access — the entire credential-theft family — without any driver.

**How:** NtQuerySystemInformation(SystemExtendedHandleInformation=0x40) into a growing buffer -> SYSTEM_HANDLE_TABLE_ENTRY_INFO_EX{Object, UniqueProcessId, HandleValue, GrantedAccess, ObjectTypeIndex}. Resolve ObjectTypeIndex once per boot by creating a known object of each type and reading its index (or NtQueryObject(ObjectTypesInformation)). For File and Process handles of interest, DuplicateHandle(sourceProc, handle, GetCurrentProcess(), &dup, 0, FALSE, DUPLICATE_SAME_ACCESS) then NtQueryObject(ObjectNameInformation) to get the path, and GetFinalPathNameByHandleW to resolve \Device\HarddiskVolumeN to a drive letter. Always duplicate on a worker thread with a 250ms watchdog — named pipes and some device handles block forever in NtQueryObject.

**False positives:** Requires PROCESS_DUP_HANDLE, i.e. elevation for anything outside the current user's non-elevated set. Anti-cheat, Defender, Everything.exe, Process Explorer/Hacker, Sysinternals tools and backup agents legitimately hold huge handle sets — allowlist by signed publisher before scoring. Never block on the duplicate; a hung enumeration must degrade to 'handle plane unavailable this cycle', not to a stalled tray app.

### [critical] T05 Event-log plane (subscriptions, not polling)
TIER: infra | SCORE: n/a. Cheap, high-precision corroboration for the defence-evasion and persistence families. Verified on this host: Defender Operational exists and is readable with 9309 records; Sysmon is absent; 4688 cannot be assumed.

**How:** System.Diagnostics.Eventing.Reader.EventLogWatcher with EventLogQuery per channel. Subscribe: 'Microsoft-Windows-Windows Defender/Operational' (1006/1007/1015/1116/1117 detections; 5001 RTP disabled; 5007 configuration changed — this is the exclusion-added event; 5010/5012 scanning disabled; 5013 tamper protection blocked), 'Microsoft-Windows-PowerShell/Operational' (4104 script block — fires for auto-flagged suspicious content even with policy off, 4103 pipeline), 'Microsoft-Windows-Sysmon/Operational' (opportunistic; absent here), 'Security' (1102 log cleared, 4720 user created, 4732 added to admins, 4688 only if present), 'System' (7045 service installed, 7040 start-type changed, 104 log cleared, 20001 driver install), 'Microsoft-Windows-TaskScheduler/Operational' (106 task registered, 140 task updated), 'Microsoft-Windows-Windows Firewall With Advanced Security/Firewall' (2004/2005/2006 rule added/changed/deleted).

**False positives:** Reading the Security log requires elevation; if unavailable, fall back to polling (registry watches, schtasks /query, Get-LocalGroupMember). Defender 1116 events during a normal scan of the user's own downloads folder are informational, not an incident. Do not double-count: a Defender detection and Warden's own detection on the same file are one event, not two families.

### [critical] T06 Scoring engine, decay, and the auto-action gate
TIER: infra | SCORE: n/a. Bands: <25 log only; 25-54 WATCH (elevate polling to 1s, start memory/handle inspection); 55-89 MEDIUM (modal prompt with full evidence and a one-click quarantine); >=90 HIGH (auto suspend -> kill -> quarantine). Contributions decay with a 30-minute half-life EXCEPT sticky provenance facts (unsigned, user-writable path, bad digest, masquerade) which persist for the process lifetime.

**How:** Implement as ProcessRiskState{ImmutableKey, List<ScoredSignal>{Id, Score, Family, Utc, Sticky, EvidenceJson}}. Auto-action requires ALL of: (a) total >= 90; (b) at least one signal with Tier=HIGH acting as anchor; (c) at least two distinct families represented (Network, Provenance, Lineage, CommandLine, CredentialAccess, Evasion, Resource, RemoteAccess, Input); (d) the process fails no veto — vetoes are: protected-process list (see T07), signed by an allowlisted publisher with a valid chain, image under a user-approved dev path, PID<100, session 0 service with a Microsoft signature; (e) learning mode is over. Cap any single family's contribution at 45 points so five weak signals of one type can never reach the auto band. Log every score mutation to an append-only JSONL timeline so the dashboard can show the exact arithmetic behind any action.

**False positives:** The corroboration rule is the primary FP defence — enforce it in code as a hard precondition on the kill path, not as a policy setting the user can accidentally disable. A 7-day learning mode must suppress all MEDIUM/HIGH actions on first install while the publisher, path and endpoint baselines populate.

### [critical] T07 Un-killable protected-process and protected-service list
TIER: infra | SCORE: n/a. The non-brick guarantee. Warden must be structurally incapable of terminating anything on this list regardless of score.

**How:** Hard-deny termination for: PID 0/4, smss.exe, csrss.exe, wininit.exe, winlogon.exe, services.exe, lsass.exe, lsaiso.exe, svchost.exe, fontdrvhost.exe, dwm.exe, sihost.exe, ctfmon.exe, RuntimeBroker.exe, explorer.exe (offer restart instead of kill), MsMpEng.exe, MpDefenderCoreService.exe, SecurityHealthService.exe, WUDFHost.exe, audiodg.exe, spoolsv.exe, and any process where GetProcessInformation(ProcessProtectionLevelInfo) reports a non-zero protection level or IsCriticalProcess (NtQueryInformationProcess ProcessBreakOnTermination) is TRUE. Verify path is under %SystemRoot%\System32 or \SysWOW64 before granting the exemption so a masquerading copy gets no protection. Before any kill: NtSuspendProcess first, snapshot full evidence, then TerminateProcess; if the process is a service host, refuse and route to a service-stop prompt instead.

**False positives:** A hollowed real svchost.exe still must not be killed by Warden — the correct response is quarantine of the persistence mechanism plus a prompt recommending reboot/Defender scan, never termination of a critical process.

### [critical] D01 Low-jitter periodic beaconing to a fixed endpoint
TIER: MEDIUM (HIGH when combined with unsigned + user-writable path) | SCORE: +35 base, +10 if the endpoint is a raw IP with no DNS-cache backing, +10 if interval is in the 30-900s C2 band. The core RAT indicator. Compute over connection-start timestamps per (pid, remoteIP, remotePort) tuple.

**How:** From the T02 event stream, keep a ring buffer of connection-open timestamps per tuple over a 2-hour window. Require N >= 8 intervals before ANY alert (this is the hard minimum — below 8 the CV statistic is meaningless). Compute intervals dt_i, mean, stddev, and CV = stddev/mean. Alert when CV <= 0.20 AND mean is between 20s and 1800s AND the endpoint is external (not RFC1918/loopback/CGNAT/BlueStacks bridge). Add a jitter-resistant second statistic: MAD/median <= 0.25, and require both to agree. Also compute a Fourier-free autocorrelation check — bucket connection starts into 1s bins over the window and score the max autocorrelation lag; a lag with r >= 0.6 corroborates. Score scales: CV<=0.05 => +45 (machine-perfect timing), CV<=0.10 => +40, CV<=0.20 => +35.

**False positives:** This host is a minefield: npm/pnpm registry polling, cargo/crates.io, VS Code and JetBrains update checks, Windows Update, OneDrive/Dropbox sync, Discord/Slack heartbeats, Steam/Epic/Blender licence pings, Unreal Insights, telemetry from the Claude Code CLI itself, and BlueStacks Google-Play heartbeats all beacon with low jitter. Suppress entirely for allowlisted-publisher signed binaries; suppress for browsers and for any process whose parent chain includes a terminal/IDE the user is actively typing in; and require the unsigned-or-user-writable provenance flag before this detection may contribute more than +10.

### [high] D02 Beacon endpoint has no DNS-cache provenance (hardcoded IP C2)
TIER: MEDIUM | SCORE: +20. Legitimate software almost always resolves a name first; commodity RATs and stagers frequently connect to a literal IP embedded in config.

**How:** On each CONNECT event, look up the remote IP in the DNS cache snapshot (T02) covering the last 15 minutes. If no A/AAAA record in the cache maps to it, and it is not in a CDN/anycast allowlist, and not RFC1918/loopback, flag 'no-DNS-provenance'. Strengthen by checking whether the process itself has any DNS activity at all (a process making TCP connections with zero cache-correlated names over 30 minutes is anomalous).

**False positives:** DoH-enabled browsers (Chrome/Firefox/Edge with secure DNS on) bypass the Windows resolver entirely, so every browser connection looks hardcoded — hard-exclude browsers and any process with a loaded chrome_elf.dll/xul.dll. Also exclude P2P and game traffic (Steam datagram relay, Epic/EOS, BlueStacks), WebRTC, NTP, and anything the user's own dev code connects to by IP (local Docker, LAN devices, the D:\My projects test harnesses).

### [critical] D03 Unsigned binary in a user-writable directory making external egress
TIER: MEDIUM | SCORE: +30 (+15 more if the directory is %TEMP%, %APPDATA%, %LOCALAPPDATA%, Downloads, Public, ProgramData root, or a Recycle Bin path). The workhorse context signal that gates half the other detections.

**How:** Join T03 (signature=TRUS T_E_NOSIGNATURE or untrusted root) with T02 (first external CONNECT). Classify the path: user-writable = anything not under %SystemRoot%, %ProgramFiles%, %ProgramFiles(x86)%, or a directory whose ACL denies write to the current user (check with GetNamedSecurityInfo/AccessCheck rather than string matching, so a writable subdir of Program Files is caught).

**False positives:** The single biggest FP source on this machine. node.exe from nvm/fnm under %APPDATA%, python.exe in venvs, cargo-built binaries in target\debug, Unreal's UnrealBuildTool and cooked builds, Blender addon subprocesses, Electron apps installed per-user (Discord, VS Code, Slack, Postman) and the user's own slot-math simulators all match. Mitigation: score 0 for binaries under a registered dev path, for children of a developer parent (cargo, node, npm, python, dotnet, msbuild, cl.exe, code.exe, WindowsTerminal), and for anything whose file was written by a process Warden itself observed compiling. Require D01/D07/D12-class corroboration before this leaves the WATCH band.

### [critical] D04 Signature present but digest invalid, revoked, or chain-broken
TIER: HIGH (anchor) | SCORE: +55. A binary that claims a signature and fails the digest has been patched post-signing — this is near-zero-FP and is the strongest single provenance signal available in usermode.

**How:** WinVerifyTrust returns TRUST_E_BAD_DIGEST (0x80096010), CERT_E_REVOKED (0x800B010C), or CERT_E_UNTRUSTEDROOT (0x800B0109) while an embedded WIN_CERTIFICATE is present in the PE (parse IMAGE_DIRECTORY_ENTRY_SECURITY to confirm a certificate table actually exists — this distinguishes 'tampered' from 'never signed'). Escalate to +70 if the subject claims a Microsoft/NVIDIA/Epic identity.

**False positives:** Self-signed dev certs and test-signed drivers produce CERT_E_UNTRUSTEDROOT legitimately — score those at +15, not +55, and allowlist any root the user has explicitly trusted. Some installers and game launchers self-patch signed binaries (Unreal's hot-reload DLLs, BlueStacks' HD-Player patched for root — the user's own memory notes this patching). Expired-but-timestamped signatures (CERT_E_EXPIRED with a valid countersignature) are VALID and must score 0.

### [critical] D05 System-binary name outside its canonical directory (masquerading)
TIER: HIGH (anchor) | SCORE: +50. svchost.exe, lsass.exe, csrss.exe, services.exe, taskhostw.exe, dllhost.exe, rundll32.exe, conhost.exe, winlogon.exe, explorer.exe, spoolsv.exe, smss.exe, wininit.exe or SearchIndexer.exe running from anywhere other than %SystemRoot%\System32, \SysWOW64 or \WinSxS.

**How:** Compare Path.GetFileName(QueryFullProcessImageNameW result) against a canonical map of system image names to allowed directories. Also verify the signer is Microsoft Windows/Microsoft Windows Publisher for any process using one of those names, regardless of location. Add +20 for a trailing-space or homoglyph variant ('svch0st.exe', 'scvhost.exe', 'explorer .exe') detected by Levenshtein distance <=1 from a system name combined with a non-System32 path.

**False positives:** WinSxS, servicing stacks, and Windows Sandbox/Hyper-V container images legitimately host copies. BlueStacks and other Android emulators ship processes with generic names; check the full path against the emulator install dir. Never flag a System32 binary running from \??\C:\Windows\System32 with the volume-GUID form of the path — normalise paths through GetFinalPathNameByHandleW before comparing.

### [high] D06 Wrong parent for a well-known system process
TIER: MEDIUM | SCORE: +30 (+15 if the parent is unsigned). svchost.exe not parented by services.exe; lsass.exe/services.exe not parented by wininit.exe; csrss.exe/wininit.exe/winlogon.exe not parented by smss.exe; explorer.exe not parented by userinit.exe or an already-exited shell launcher; taskhostw.exe not parented by svchost.exe.

**How:** Resolve the parent using the PID+creationTime key from T01, and verify the parent's creation time PRECEDES the child's — an earlier-created child proves PID reuse and the lineage must be discarded as unknown rather than scored. Compare against a static expected-parent map.

**False positives:** Legitimate orphaning is constant on Windows: explorer.exe restarts, Task Manager 'Run new task', anything launched from an elevated context, and parents that exit immediately (installers, updaters). Treat 'parent exited' as unknown, not as wrong. Anti-cheat and virtualisation shims reparent processes. Only score when the parent is present, alive, and demonstrably wrong.

### [critical] D08 Encoded PowerShell command line
TIER: HIGH (anchor) | SCORE: +45, plus the full score of whatever the decoded content itself triggers (D09/D10 rescored on the plaintext).

**How:** Match the command line (from T01 PEB read) against -e/-en/-enc/-encod/-EncodedCommand/-ec (PowerShell accepts any unambiguous prefix) followed by a base64 blob. Decode as UTF-16LE, then re-run D09, D10 and D11 over the plaintext and attach the decoded text to the evidence record so the prompt shows the user exactly what would have run. Also flag FromBase64String, [Convert]::FromBase64String, -EncodedArguments, and gzip/deflate-wrapped payloads ([IO.Compression.GzipStream] + FromBase64String in the same line).

**False positives:** Some legitimate installers, Chocolatey, and CI runners use -EncodedCommand to survive quoting. The decoded content is the discriminator — if it decodes to a benign, readable command with no download/exec pattern, cap the contribution at +10. Claude Code, VS Code tasks and npm scripts on this machine invoke pwsh with -Command containing complex quoting; that is not encoding and must not match.

### [critical] D09 Download cradle in a command line
TIER: HIGH (anchor) | SCORE: +45. Fetch-and-execute in one line is the loader signature.

**How:** Regex the command line (and any 4104 script block) for: (New-Object\s+Net\.WebClient).*(DownloadString|DownloadFile|DownloadData); Invoke-WebRequest|iwr|curl|wget followed by -OutFile/-o into %TEMP%/%APPDATA%/%PUBLIC%; Invoke-RestMethod|irm piped to iex|Invoke-Expression; certutil.*-urlcache|-decode|-encode; bitsadmin.*\/transfer; msiexec.*(http|https)://; regsvr32.*\/i:http.*scrobj\.dll; mshta.*(http|javascript:|vbscript:); rundll32.*javascript:; curl.exe piped to cmd/pwsh; [System.Net.WebClient] plus .Invoke; Start-BitsTransfer to a user dir. Score the combination fetch+execute (+45) far above fetch alone (+15).

**False positives:** This user runs install scripts (`irm https://... | iex` is the documented install path for rustup, pnpm, scoop, chocolatey, uv, bun and the Windows Package Manager bootstrap). Suppress when the parent is an interactive terminal AND the user typed within 10 seconds AND the domain is on a well-known installer allowlist (rustup.rs, get.scoop.sh, chocolatey.org, pnpm.io, bun.sh, astral.sh, aka.ms, microsoft.com, github.com releases). Prompt rather than act when it is interactive; auto-act only when the parent is non-interactive.

### [critical] D10 AMSI / logging / policy bypass patterns
TIER: HIGH (anchor) | SCORE: +50. There is no benign reason for user code to patch AMSI.

**How:** Match on command line and 4104 script blocks for: AmsiUtils, amsiInitFailed, AmsiScanBuffer, [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils'), SetValue($null,$true) near amsi, VirtualProtect+amsi.dll, 'System.Management.Automation.Utils'+'cachedGroupPolicySettings' (ETW/transcription bypass), [Reflection.Assembly]::Load with a byte array, EtwEventWrite patching, 'ScriptBlockLogging' registry writes from a non-admin-tool process, Add-MpPreference/Set-MpPreference from a script, and -ExecutionPolicy Bypass|Unrestricted combined with -WindowStyle Hidden|-w h and -NoProfile|-nop and -NonInteractive. Each of the last three flags alone is +5; all three together plus a network-touching child is +35.

**False positives:** -ExecutionPolicy Bypass -NoProfile is standard in CI, VS Code tasks, npm postinstall scripts and installer bootstrappers — alone it is near-worthless as a signal, which is why it scores +5. The AMSI-patching patterns themselves have no dev-workflow analogue and can be scored aggressively; the only realistic FP is a security-research file the user has open in an editor, so require that the pattern appear in a LIVE process command line or an executed 4104 block, never in a file on disk.

### [high] D11 Obfuscated command line (statistical)
TIER: LOW alone, MEDIUM in combination | SCORE: +15 alone, +30 when combined with a LOLBin image. Catches obfuscators that evade keyword matching.

**How:** Compute over the command line: Shannon entropy (>4.5 bits/char on a >200-char line), ratio of non-alphanumeric to alphanumeric (>0.35), backtick count (>8 for PowerShell), caret count (>8 for cmd), count of string-concat operators ('+' between quoted fragments >6), presence of -f format-operator reassembly, ${} variable-name obfuscation, char[] casting ([char]0x..), -join/-split reassembly, and total length >1500 chars. Sum weighted sub-scores; require at least two independent indicators.

**False positives:** Long, punctuation-dense command lines are the norm here: cl.exe/link.exe invocations, UnrealBuildTool argument blocks, ffmpeg filter graphs, node --experimental flags, cargo rustc flag soups, and Blender's --python-expr all trip naive entropy. Exclude any command line whose image is on the developer-toolchain allowlist, and exclude lines that are mostly file paths (>40% of characters inside path-shaped tokens).

### [critical] D12 Handle to lsass.exe with read/VM access from a non-allowlisted process
TIER: HIGH (anchor) | SCORE: +60. The definitive credential-dumping indicator obtainable in usermode.

**How:** From T04, find Process-type handles whose Object resolves to the lsass.exe PID. Inspect GrantedAccess for PROCESS_VM_READ (0x0010), PROCESS_QUERY_INFORMATION (0x0400), PROCESS_DUP_HANDLE (0x0040) or PROCESS_ALL_ACCESS (0x1FFFFF). Score +60 for VM_READ|QUERY_INFORMATION from an unsigned or user-dir process, +35 from a signed non-allowlisted process, +10 for QUERY_LIMITED_INFORMATION only. Corroborate with a filesystem watch for *.dmp files whose first four bytes are 'MDMP' appearing anywhere under %TEMP%, %APPDATA%, %PUBLIC%, or the user profile, and with a check for comsvcs.dll MiniDump in any command line.

**False positives:** Defender (MsMpEng.exe), Windows Error Reporting (WerFault.exe), Sysinternals procexp/procmon, Task Manager, VS/WinDbg debuggers, anti-cheat, and backup agents all open lsass handles legitimately. Allowlist by signed publisher AND path. Warden itself will hold such handles — exclude self. WerFault.exe is a real abuse vector, so allowlist it only when its parent is svchost/the crashing process and its command line contains the expected -p/-s/-t arguments.

## Risks
- FALSE POSITIVES ON DEVELOPER WORKLOADS ARE THE DOMINANT RISK. The miner family (D24/D25/D27) collides head-on with this user's slot-math Monte Carlo simulations, Unreal shader compilation, Blender Cycles renders and overnight builds — all windowless, all CPU/GPU-saturating, all running while the user is idle. If auto-kill ever reaches a build, the product is dead. Mitigation: miner detections may never anchor; they require D26 (external stratum port) as corroboration; and a one-click permanent 'this is my workload' exception must exist.
- PRIVILEGE DEPENDENCY. The handle plane (T04, and therefore D12/D13/D14 — the entire credential-theft family), TCP ESTATS byte counters (D38/D37), Defender exclusion enumeration (D17), and the Security event log (D19/D30) all require elevation. Verified on this host: Get-MpPreference exclusions and auditpol both refused unelevated. Warden must run elevated or advertise a materially reduced coverage set; silently degrading without telling the user is the worse failure.
- MISSING GROUND TRUTH FOR PROCESS CREATION. Verified: Sysmon is not installed, ProcessCreationIncludeCmdLine is not configured, and 4688 status could not be read. Warden's 2s Toolhelp poll will miss short-lived processes entirely — a stager that runs for 800ms is invisible. Do not design any detection that assumes a complete process-creation stream. Consider offering an opt-in, user-approved enablement of 4688 + command-line auditing as a Maintenance action, presented as a settings change requiring explicit consent.
- PID REUSE AND LINEAGE CORRUPTION. Windows recycles PIDs aggressively on a 24-thread machine running build farms. Any detection keyed on bare PID will eventually attribute a malicious signal to an innocent process and kill it. The PID+creationTime composite key in T01 is a correctness requirement, not an optimisation.
- HANDLE ENUMERATION HANGS. NtQueryObject(ObjectNameInformation) on synchronous named pipes blocks indefinitely; done on the UI thread or without a watchdog this freezes the tray app. Also, DuplicateHandle floods can perturb the system under load.
- SCORE INFLATION VIA CORRELATED SIGNALS. Several detections observe the same underlying fact (unsigned + user-dir + no signature + high entropy + recent write). Without the per-family cap and the two-distinct-family rule, a single benign unsigned build output can accumulate 100+ points from what is really one observation.
- REMOTE-MEMORY SCANNING COST AND STABILITY. D20's VirtualQueryEx walk over a 60GB-RAM machine's large processes (Unreal editor, Chrome, BlueStacks) is expensive and can stall; it must be watchdogged, budgeted, and never run against protected or anti-cheat-guarded processes, which may treat the read as an attack and terminate the game or ban the user.
- QUARANTINE OF AN IN-USE OR SYSTEM-CRITICAL FILE. Moving a file that a running service depends on can break boot. Quarantine must verify the file is not a loaded module of any protected process, must record the exact original path, ACL, attributes, timestamps and ADS for byte-exact restore, and must refuse anything under %SystemRoot% outright.
- OBSERVED CONTENT IS UNTRUSTED INPUT. Command lines, window titles, DNS names, file names, event-log payloads and script blocks are attacker-controlled strings. They must be treated as data everywhere: HTML/XAML-encoded before display, length-capped, control-characters stripped (including RTLO) before logging, and never passed unquoted into any shell-out. A detection engine that renders attacker text into a WPF dashboard is an injection surface.
- ALERT FATIGUE COLLAPSING INTO BLIND APPROVAL. If MEDIUM prompts fire more than roughly once a week on this machine, the user will click through them reflexively and the auto-kill tier becomes the only functioning control. Instrument the prompt rate and treat >2/week as a tuning defect.

## Implementation notes
ORDER OF BUILD. Ship the telemetry planes first and run them in observe-only mode for a week on this actual machine before wiring any scoring: T01 process plane, T02 socket plane, T03 signature cache, T05 event subscriptions. Log everything to append-only JSONL. Then implement D01, D03, D07, D08, D09, D17, D26, D28, D31, D36 — that subset alone covers most real-world RAT/stealer/miner/loader activity at high precision. The handle plane (T04) and memory plane (D20) come last because they are the most expensive and the most likely to destabilise.

PLATFORM SPECIFICS. Target net10.0-windows with UseWPF and UseWindowsForms. Prefer LibraryImport source-generated P/Invoke over DllImport (net10 default, avoids marshalling stubs). Set <AllowUnsafeBlocks>true</AllowUnsafeBlocks> for the memory and handle structs. Use SafeHandle-derived wrappers for every kernel handle — a leaked process handle in a 2-second polling loop exhausts the machine within hours. Structures that differ between x64 and WOW64 (PEB, RTL_USER_PROCESS_PARAMETERS, SYSTEM_HANDLE_TABLE_ENTRY_INFO_EX) need explicit layouts with hardcoded offsets and a runtime architecture check; do not rely on sizeof.

ELEVATION. Manifest requestedExecutionLevel=highestAvailable and detect actual elevation at runtime via WindowsPrincipal.IsInRole(Administrator). Register the autostart entry as a Scheduled Task with 'Run with highest privileges' and trigger 'At log on' rather than a Run key, so the tray app starts elevated without a UAC prompt every boot. The task's action must point at a fixed install path; validate the binary's own signature/hash at startup so the task cannot be repointed.

UNDOCUMENTED APIS TO GUARD. NtQuerySystemInformation(SystemExtendedHandleInformation=0x40), NtQueryInformationProcess, NtQueryObject and DnsGetCacheDataTable are undocumented or semi-documented and may change. Wrap each in a capability probe at startup that verifies the returned shape (e.g. confirm the handle enumeration finds Warden's own known handles) and disables the dependent detections cleanly if the probe fails, rather than crashing or producing garbage attributions.

BUFFER PROTOCOL. NtQuerySystemInformation returns STATUS_INFO_LENGTH_MISMATCH (0xC0000004) and the required size is a moving target on a busy machine — loop with a growing buffer (start 1MB, x2, cap 64MB) and a retry limit. Same pattern for GetExtendedTcpTable (ERROR_INSUFFICIENT_BUFFER).

PERFORMANCE BUDGET. The tray process must sit under roughly 1% of one core and 150MB working set at idle on this 12900K. Achieve it by: caching signature verdicts by (path,size,mtime,partial-hash); only re-reading command lines for newly-seen PIDs; running the handle plane at 15s and only escalating for watchlisted processes; running the memory plane on-demand only; using EventLogWatcher subscriptions instead of log polling; and batching the WMI fallback into one query per 10s rather than per-process. Put every plane on its own dedicated thread with a Channel<T> feeding a single-threaded scoring loop, so a hung P/Invoke degrades one plane instead of the app.

SHELL-OUTS. Acceptable and useful for: Get-DnsClientCache (verified working unelevated), Get-MpPreference/Get-MpComputerStatus, auditpol queries, schtasks /query /xml, netsh advfirewall show, winget list. Always invoke with ProcessStartInfo UseShellExecute=false, RedirectStandardOutput=true, CreateNoWindow=true, an explicit full path to the executable in System32 (never bare name, to avoid path hijack), -NoProfile for PowerShell, arguments passed via ArgumentList (never a concatenated string), and a hard timeout with process-tree kill. Never interpolate observed content into a shell-out.

COM WITHOUT NUGET. Firewall rules via dynamic COM on HNetCfg.FwPolicy2 (INetFwPolicy2.Rules), shell links via Shell32's IShellLink/IPersistFile, and WMI via System.Management (in-box) or the WMI COM interfaces. All reachable without a package reference.

LEARNING MODE MECHANICS. Seven days, or 3 days plus 500 distinct process-image observations, whichever is later. During it: collect everything, score everything, act on nothing above LOW, and build (a) the publisher allowlist from every signed binary seen, (b) the dev-path allowlist from directories containing .git/Cargo.toml/package.json/.uproject/.sln, (c) the per-process network endpoint and volume baseline, (d) the listener baseline, (e) the ASEP baseline. Show a 'learning: day 3 of 7' banner so the user understands why it is quiet.

EVIDENCE AND REVERSIBILITY. Every action writes an incident record containing the full scoring arithmetic, every contributing signal with its raw evidence, a copy of the process's command line and module list, the socket table rows involved, and the file's hash and signature verdict. Quarantine: move to a per-incident folder under a protected vault directory, rename to <sha256>.quarantine, strip the execute ACE and set the file read-only, record the original path/ACL/timestamps/attributes/ADS in a sidecar JSON, and expose a one-click restore that replays them exactly. Kill sequence is always suspend -> snapshot -> terminate, so a wrong decision on a long-running build can be caught and resumed before termination if the user is present.

SELF-EXCLUSION. Warden's Maintenance half will legitimately clear logs, delete temp files, disable startup items and change settings. Tag every Maintenance action with an in-process correlation token and have the Guardian half suppress detections attributable to it — otherwise the app will detect itself as an attacker."

- **Claim:** T04/D12: 'For File and Process handles of interest, DuplicateHandle(..., DUPLICATE_SAME_ACCESS) then NtQueryObject(ObjectNameInformation) to get the path' — used to resolve Process handles to the lsass PID.

Note the late-binding route breaks under PublishTrimmed/PublishAot, which the notes elsewhere anticipate for Warden's own single-file build.
- **Claim:** T06 auto-action gate: total >= 90, one HIGH anchor, 'at least two distinct families', per-family cap 45.
  - **Why wrong:** The arithmetic makes the corroboration rule non-binding for exactly the binaries this user produces. Provenance facts are declared sticky and never decay, so any unsigned binary under %APPDATA%/%TEMP% permanently holds D03 at +45 (capped). A single network detection at its own cap — D01 at CV<=0.05 (+45), D26 (+45), D32 (+50->45) — then reaches exactly 90 with two 'distinct' families. The families are not independent: D01 explicitly states it 'may [not] contribute more than +10' without the unsigned-or-user-writable provenance flag, i.e. the Network score is conditioned on the Provenance fact. Two signals derived from one observation satisfy a rule written to require two observations.
  - **Fix:** Demote sticky provenance from a scoring family to a gate/multiplier that cannot itself count toward the two-family requirement. Add an explicit family-independence matrix and reject pairs where one detection's precondition is the other's output. Raise the auto band above the sum of any two family caps (e.g. cap families at 35 with a 90 threshold, forcing three independent families). Add a global circuit breaker: at most one autonomous kill per hour, and never a second before a human has reviewed the first.
- **Claim:** T01: 'Open with PROCESS_QUERY_LIMITED_INFORMATION and call ... NtQueryInformationProcess(ProcessBasicInformation) to get PebBaseAddress, ReadProcessMemory the PEB'.
  - **Why wrong:** ReadProcessMemory requires PROCESS_VM_READ, which PROCESS_QUERY_LIMITED_INFORMATION does not confer. As written every command-line read fails with ERROR_ACCESS_DENIED and the design silently falls through to the (unavailable) WMI path, so D08/D09/D10/D11/D17/D18/D19/D26/D29/D30/D43/D44 — every command-line detection — produce nothing.
  - **Fix:** Open with PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ, fall back to QUERY_LIMITED alone for the identity fields when VM_READ is refused, and record 'cmdline unavailable' distinctly as the spec already requires. Cache the result per PID+creationTime; the PEB command line never changes after start.
- **Claim:** T02: 'SetPerTcpConnectionEStats / GetPerTcpConnectionEStats(TcpConnectionEstatsData) -> TCP_ESTATS_DATA_ROD_v0.DataBytesOut/DataBytesIn'.
  - **Why wrong:** Those two functions take MIB_TCPROW and are IPv4-only. IPv6 connections require SetPerTcp6ConnectionEStats/GetPerTcp6ConnectionEStats with MIB_TCP6ROW, which the spec never mentions — so on a Windows 11 host where a large share of traffic is IPv6, D37/D38 have no byte counters at all. Separately, ESTATS is TCP-only: QUIC/HTTP-3 (Chrome, Edge, Google, Cloudflare, and increasingly CDNs) is UDP and produces zero bytes in this plane, so 'anomalous outbound volume' is blind to the most likely modern exfil transport.
  - **Fix:** Implement both the v4 and v6 ESTATS pairs. State QUIC/UDP as an explicit blind spot in D48 and add a coarse UDP substitute: per-PID UDP endpoint churn plus datagram counts from GetPerTcpConnectionEStats' absence, or simply flag sustained UDP/443 from a non-browser, non-allowlisted process as a separate low-score signal. Also remember to call Set...EStats with EnableCollection=FALSE on close; leaving collection enabled per connection has real kernel cost on a machine with thousands of sockets.
- **Claim:** T02: 'Enrich remote IPs from the DNS cache via DnsGetCacheDataTable (dnsapi.dll)'.
  - **Why wrong:** DnsGetCacheDataTable returns a linked list of DNS_CACHE_ENTRY {pNext, pszName, wType, wDataLength, dwFlags}. It contains names and record types only — no resolved addresses. It cannot give you the IP->name mapping D02 and D39 are built on.
  - **Fix:** Enumerate names with DnsGetCacheDataTable, then call DnsQuery_W per name with DNS_QUERY_NO_WIRE_QUERY to read the cached A/AAAA records without touching the network. Better still, drop this plane for Microsoft-Windows-DNS-Client ETW (see omissions), which gives query, answer and owning PID authoritatively.
- **Claim:** T04: 'Always duplicate on a worker thread with a 250ms watchdog — named pipes and some device handles block forever in NtQueryObject.'
  - **Why wrong:** A watchdog that abandons the thread is not a mitigation on modern .NET: Thread.Abort throws PlatformNotSupportedException on .NET 5+, so every hung query permanently leaks a thread (and the duplicated handle). At a 15s cadence over days on a machine running Docker/BlueStacks/dev servers with many synchronous pipes, this is unbounded thread and handle growth in the process that is supposed to never destabilise the host.
  - **Fix:** Pre-filter instead of racing: resolve the File ObjectTypeIndex and skip everything else; skip entries whose GrantedAccess is 0x0012019F (the well-known synchronous-pipe mask); and prefer GetFinalPathNameByHandleW(VOLUME_NAME_DOS) over NtQueryObject. If a query mechanism that can still hang is retained, run it in a separate sacrificial child process that can be terminated, not a thread.
- **Claim:** T05/D34: subscribe to 'Microsoft-Windows-TaskScheduler/Operational' 106/140 for task registration, plus 141 for deletion.
  - **Why wrong:** Verified on this host: that log's IsEnabled is False and RecordCount is empty. It is disabled by default on Windows 10/11. The subscription will attach and never deliver, so scheduled-task persistence detection silently produces nothing while the dashboard shows the plane as healthy.
  - **Fix:** Either (a) present enabling the channel as an explicit, consented Maintenance action (wevtutil sl 'Microsoft-Windows-TaskScheduler/Operational' /e:true) and show the plane as degraded until then, or (b) drop the log entirely and watch HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree with RegNotifyChangeKeyValue, which also catches registry-only task creation that never writes a file under System32\Tasks.
- **Claim:** T05/D08/D10: 'Microsoft-Windows-PowerShell/Operational (4104 script block — fires for auto-flagged suspicious content even with policy off)'.
  - **Why wrong:** True for Windows PowerShell 5.1 only. PowerShell 7 logs to PowerShellCore/Operational, and verified on this host that channel does not exist at all — while the user's shell is pwsh 7.6.5. Every 4104 corroborator (D07, D08, D09, D10) is therefore unavailable for the shell the user actually runs, and the AMSI-bypass family in particular loses its only non-command-line evidence source.
  - **Fix:** State the limitation explicitly in the coverage panel. Subscribe to PowerShellCore/Operational when present, offer registering/enabling it as a consented action, and do not treat the absence of 4104 as absence of PowerShell activity.
- **Claim:** D22: flag 'an import table with fewer than 10 imports total' and 'an entry point outside any section'.
  - **Why wrong:** Both fire on essentially every managed assembly. A .NET DLL has AddressOfEntryPoint = 0 (outside every section) and imports either nothing or the single legacy mscoree!_CorExeMain stub. This machine has tens of thousands of managed DLLs, the user builds .NET daily, and Warden itself is .NET — so D22 tags its own binaries. Go and statically-linked Rust output trips the same two sub-checks.
  - **Fix:** Skip the import/entry-point heuristics whenever IMAGE_DIRECTORY_ENTRY_COM_DESCRIPTOR (index 14) is non-zero, i.e. the file has a CLR header. Add a separate exclusion for AddressOfEntryPoint == 0 in DLLs generally, and do not count static-link-heavy toolchain output (Go, Rust) as import-starved.
- **Claim:** D20: 'Flag regions where State=MEM_COMMIT and Protect includes PAGE_EXECUTE_READWRITE / PAGE_EXECUTE_WRITECOPY'.
  - **Why wrong:** PAGE_EXECUTE_WRITECOPY is the normal protection for executable pages of a mapped image (MEM_IMAGE) — it is what a copy-on-write .text section looks like. Flagging it without restricting to MEM_PRIVATE matches most loaded modules in most processes.
  - **Fix:** Restrict the WRITECOPY case to Type == MEM_PRIVATE, or drop it and score only MEM_PRIVATE with PAGE_EXECUTE_READWRITE / PAGE_EXECUTE_READ that is not covered by any EnumProcessModulesEx range.
- **Claim:** D20: 'reading the first 4KB of the main module's .text from memory and comparing to the on-disk file's mapped equivalent — a mismatch in a signed binary is definitive' (+60, HIGH escalation).
  - **Why wrong:** Not definitive, and it is the escalation path into the auto-kill band. In-memory .text legitimately differs from disk because of base relocations when the image is not loaded at its preferred base, import-address and Control Flow Guard fixups, loader import optimisation on Windows 11, /hotpatch padding, and legitimate self-patching (Detours-style hooks used by overlays, profilers, anti-cheat, and Unreal/Blender plugin systems).
  - **Fix:** Apply the relocation delta and mask CFG/IAT-adjacent bytes before comparing, exclude any process with a known hooking/overlay/anti-cheat module loaded, and demote the result from 'definitive' to a MEDIUM corroborator that can never anchor an autonomous action.
- **Claim:** D26: outbound TCP to ports 3333/4444/5555/6666/7777/8888/9999... and 'TLS variants 443 where the connection is single, long-lived (>30 min), low-volume-in/steady-volume-out ... paired with high CPU'.
  - **Why wrong:** 7777 is the Unreal Engine default game/server port and this is an Unreal developer's machine. The 443 shape described — one long-lived connection, small inbound, steady outbound, while the CPU is busy — is the exact shape of every WebSocket and long-poll on the host: Discord gateway, Slack, VS Code Live Share/Settings Sync, Steam, Epic/EOS, the Claude Code CLI's own streaming connection. D26 is the mandated corroborator that lets the miner family act, so this is the path by which an overnight build reaches the auto band: D24 (+35 Resource) + D26 (+45 Network, HIGH anchor when combined with D24) + D03 (+45 Provenance on an unsigned self-built simulator) = 125, three families, anchor present, auto-kill.
  - **Fix:** Remove 7777 from the pool-port list. Delete the port-agnostic 443 shape test entirely, or require an actual pool-hostname match from the DNS plane or a stratum-shaped command line before D26 may score above +10. Hard-cap the combined Resource+miner contribution below the auto-action threshold so the miner family can only ever prompt, matching the stated risk mitigation.
- **Claim:** D25: 'flag explicit idle-detection behaviour: the process calling SetThreadExecutionState'.
  - **Why wrong:** Not observable. There is no usermode API in any of the six declared telemetry planes that reports another process calling SetThreadExecutionState; it leaves no handle, no memory artefact and no event-log record.
  - **Fix:** Drop it, or replace it with the observable proxy: parse 'powercfg /requests' (admin, System32 path, already an accepted shell-out) which lists the processes currently holding EXECUTION/DISPLAY/SYSTEM power requests.
- **Claim:** D42/D46: flag 'a session-0 process owning a visible window'.
  - **Why wrong:** EnumWindows enumerates only windows on the calling thread's desktop within its window station. A Warden running in the interactive session can never see a session-0 window, so this rule can never fire. (Session 0 isolation has made this condition unobservable and largely impossible since Vista.)
  - **Fix:** Delete the rule. If cross-session visibility is genuinely wanted, it requires EnumDesktopWindows against WinSta0 desktops plus impersonation, which is not worth the complexity for a dead signal.
- **Claim:** D17: 'Corroborate with a 60s poll of HKLM\SOFTWARE\Microsoft\Windows Defender\Exclusions\* (readable only when elevated)'.
  - **Why wrong:** With Tamper Protection on — the default on Windows 11 — that key is ACL'd such that even an elevated administrator cannot read the Exclusions subtree; access is restricted to the Defender service itself. Elevation is necessary but not sufficient. The policy-set mirror at HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Exclusions is readable but only reflects GPO-set exclusions, not ones added with Add-MpPreference.
  - **Fix:** Use Get-MpPreference (as admin) or the MSFT_MpPreference class in root\Microsoft\Windows\Defender, and treat the registry as a supplementary policy-only view. Show 'exclusion enumeration unavailable' rather than reporting an empty list as 'no exclusions'.
- **Claim:** D43: 'System 7045 for a service whose image is an unsigned .sys in a user directory (bring-your-own-vulnerable-driver: +70)'.
  - **Why wrong:** Backwards. Driver Signature Enforcement on x64 Windows 11 means an unsigned .sys cannot load at all, so the +70 case is the one that cannot happen. Real BYOVD uses a validly signed but vulnerable driver (and on Win11 the Microsoft vulnerable-driver blocklist plus HVCI already block many of them).
  - **Fix:** Score on any new kernel-mode service whose ImagePath is outside %SystemRoot%\System32\drivers, regardless of signature; check the image against the Microsoft recommended-driver-blocklist hashes shipped with the app; and treat a signed driver from a user-writable or vendor-unrelated path as the anchor. Baseline the BlueStacks/ReZygisk driver set during learning as the spec already notes.
- **Claim:** T03: 'WinVerifyTrust(... dwStateAction=WTD_STATEACTION_VERIFY ...)' with signer identity via X509Certificate.CreateFromSignedFile.
  - **Why wrong:** Two problems. (1) Every WTD_STATEACTION_VERIFY call allocates provider state that must be released by a second WinVerifyTrust call with WTD_STATEACTION_CLOSE and the returned hWVTStateData; the spec never closes it, so a tray process verifying binaries continuously leaks memory and crypto handles indefinitely. (2) System32 binaries are catalog-signed, not embedded-signed: a plain WINTRUST_FILE_INFO verify returns TRUST_E_NOSIGNATURE for them and CreateFromSignedFile yields no signer, so 'verify the signer is Microsoft Windows for any process using one of those names' (D05) fails for the genuine articles.
  - **Fix:** Always pair VERIFY with a CLOSE call in a finally block. Read signer identity from the verify state via WTHelperProvDataFromStateData -> WTHelperGetProvSignerFromChain -> WTHelperGetProvCertFromChain before closing, and for catalog-signed files take the signer from the catalog obtained via CryptCATAdminAcquireContext2/CryptCATAdminEnumCatalogFromHash. Also verify by handle (WINTRUST_FILE_INFO.hFile on an open, share-denied handle) rather than by path, to close the swap-between-verify-and-execute window.
- **Claim:** D01: 'keep a ring buffer of connection-open timestamps per tuple over a 2-hour window. Require N >= 8 intervals ... Alert when CV <= 0.20 AND mean is between 20s and 1800s'.
  - **Why wrong:** Internally impossible at the top of the range: 8 intervals at a 1800s mean spans 4 hours, so no beacon slower than ~900s can ever satisfy N>=8 inside a 2-hour window, and the advertised '+10 if interval is in the 30-900s C2 band' is the only band that is actually reachable. Separately, a 5s poll drops any connection shorter than the interval; a single missed beacon turns two intervals of T into one of 2T, which inflates CV far past 0.20 and suppresses the detection precisely when the target is stealthiest.
  - **Fix:** Either widen the window to >= 4x the maximum mean or cap the mean at 600s. Replace raw CV with a lattice fit: estimate the base period (e.g. by minimising residuals of dt_i modulo T over candidate T) so dropped observations register as k*T rather than as jitter, then score the residual dispersion. Also state in D48 that a beacon riding a persistent keep-alive connection produces one CONNECT event and is invisible to this detection entirely.
- **Claim:** D15: '+50 only when the user-data-dir is the real profile or absent'.
  - **Why wrong:** Chrome and Edge have refused --remote-debugging-port/--remote-debugging-pipe when the data directory is the default profile since Chrome 136 (2025), specifically to kill this technique. The highest-scoring branch is now unreachable on a current browser, while the real modern variants — pointing --user-data-dir at a *copy* of the profile, or driving the App-Bound Encryption elevation service COM interface — are not covered.
  - **Fix:** Keep the rule but add: a new directory that structurally matches a Chrome User Data profile (Local State + Default\Login Data) created outside the browser's own path, and any non-browser process invoking the Chrome/Edge elevation service COM class. Reduce the weight of the --user-data-dir test accordingly.
- **Claim:** D10 scores 'Add-MpPreference/Set-MpPreference from a script' at +50 HIGH anchor, while D17 says a user-intent exclusion is '+0, log only'.
  - **Why wrong:** Direct contradiction between two detections operating on the same observable. As written, the user typing Add-MpPreference -ExclusionPath 'D:\My projects' in an elevated terminal — an action D17's own FP notes call 'real and common' for this developer — trips D10 for +50 as a HIGH anchor and D17 for +60, i.e. 110 points and two families, from one deliberate keystroke sequence.
  - **Fix:** Make D17 the single owner of Defender-policy observations and have D10 exclude the Mp* cmdlets entirely. Apply the interactive/foreground/elevated-terminal discriminator once, in D17, and require it to hold for both scores.
- **Claim:** D16: 'RegNotifyChangeKeyValue (via a background thread on a duplicated key handle)'.
  - **Why wrong:** Two runtime traps. The notification is one-shot and must be re-armed after every signal, and — critically for a .NET app — an asynchronous registry notification is cancelled when the thread that registered it exits, which on a ThreadPool thread happens unpredictably. The subscription then dies silently and the WDigest/LSA/UAC watch reports 'no changes' forever.
  - **Fix:** Pass REG_NOTIFY_THREAD_AGNOSTIC (0x10000000) alongside REG_NOTIFY_CHANGE_LAST_SET, use asynchronous mode with a dedicated event handle waited on by a long-lived owned thread, re-arm inside the wait loop, and keep the HKEY alive for the process lifetime. Apply the same to the D34 registry ASEP watches.
- **Claim:** D24/D07/D09/D19/D29: use GetLastInputInfo to establish 'the user provided input within N seconds' as a suppressor.
  - **Why wrong:** GetLastInputInfo is a single session-global timestamp that any process can reset by calling SendInput or mouse_event; it does not say which process received input, or that input was even human. Malware that wants to defeat D24/D25 or unlock the D07/D09/D19 suppressors only has to inject a synthetic mouse move once a minute.
  - **Fix:** Never let user-activity evidence suppress or downgrade a HIGH-tier detection; use it only to choose 'prompt' over 'act' (which is the safe direction). Corroborate with a second, harder signal for the cases that matter: the foreground window belongs to the process's own console/terminal, plus raw-input device timestamps, plus WTS session lock state.
- **Claim:** D06/D07: parent identity is established from the T01 PPID + creation-time key and treated as trustworthy lineage.
  - **Why wrong:** PPID is a value the creator chooses. Any process can set an arbitrary parent with PROC_THREAD_ATTRIBUTE_PARENT_PROCESS, so the LOLBin-lineage family is one line of code away from evasion. Legitimately, Windows already breaks this: a UAC-elevated launch is reparented to the AppInfo service host, so 'Run as administrator' on any tool shows a Microsoft-signed svchost.exe as its parent. D07's suppressors (explorer.exe->pwsh with recent input) and D06's expected-parent map both misread these.
  - **Fix:** Record lineage as 'reported parent' and mark it low-confidence. Treat a svchost/AppInfo parent as 'elevation broker — real parent unknown'. Where it matters, recover the true creator from ETW ProcessStart (which carries the creating process id independently) rather than the PEB/PPID.

### Safety objections
- Quarantining a driver or service binary can make the machine unbootable. The spec's only quarantine guard is 'refuse anything under %SystemRoot%', which does not cover a .sys or service EXE under Program Files (BlueStacks, anti-cheat, VPN, virtualisation). Moving the image of a service whose Start value is 0 (boot) or 1 (system) produces a boot failure, not a broken app. Quarantine must query the SCM for any service whose ImagePath resolves to the file, refuse outright for Start<=1, and for anything else disable the service first, record the original Start value, and require a reboot-and-verify step before the move is considered committed.
- Quarantine is specified as 'move to a per-incident folder under a protected vault directory'. If the vault is on C: and the file is on D:, E: or F: — where this user's projects and assets live — this is not a move but a copy plus delete across volumes. That is non-atomic (a failure mid-operation loses the file), it does not preserve alternate data streams (which the spec elsewhere says it must restore byte-exactly), and it silently rewrites ACLs and object IDs. Either keep a per-volume vault so every quarantine is a same-volume MoveFileEx rename, or use CopyFile2 with explicit ADS enumeration plus verified hash before unlinking the original.
- Kill sequence is 'always suspend -> snapshot -> terminate'. If Warden crashes, is killed, or is updated between the suspend and the decision, the target stays suspended forever with no recovery path — the user sees a hung, unkillable-looking application with no explanation. This is a realistic way to hang a build, an Unreal editor with unsaved work, or the shell. Persist every suspension to disk before issuing it, resume everything unrecognised on startup, and have the suspending thread hold a watchdog that auto-resumes after N seconds if no decision arrives.
- Nothing prevents suspending or killing a process the user is actively looking at. The most damaging possible false positive is terminating the foreground window's process, or suspending dwm.exe/explorer.exe/a full-screen game. Add a hard precondition to both suspend and kill: the target must not own the foreground window, must not own any visible top-level window unless the user confirms, and must not be within the protected set.
- There is no data-loss guard on the kill path. Terminating a process that has been running for six hours — the user's Monte Carlo simulation, an Unreal cook, a Blender render — destroys work that cannot be recovered from a quarantine vault, because the loss is in memory, not on disk. Any process older than a few minutes, or with substantial accumulated CPU time, should be capped at suspend-and-prompt regardless of score.
- The autostart design — a Scheduled Task with 'Run with highest privileges' pointing at a fixed install path — is a local privilege-escalation primitive if that path is user-writable, and the proposed mitigation ('validate the binary's own signature/hash at startup so the task cannot be repointed') is circular: the code doing the validation is the code an attacker replaced. The install directory must be created with an ACL granting the user read/execute only, under %ProgramFiles%, and the task action must be pinned to that path. Note also that the same technique (highest-privileges logon task) is what Warden's own D34/D47 will flag on other software, so the self-exclusion token has to cover it.
- The 'second lightweight guardian process that each restart the other' is the mutual-watchdog pattern D41 scores as malicious, and it makes Warden difficult for its own owner to stop. If a heuristic regression ships, the user's only recourse against a process pair that resurrects itself and holds handles to everything is Safe Mode. Replace it with a single component plus an always-available, documented kill switch and a Safe-Mode-friendly disable flag; do not build resurrection logic into a tool whose primary risk is acting wrongly.
- The append-only JSONL timeline is specified to contain 'a copy of the process's command line' for every scored process. On a developer machine command lines routinely carry secrets: npm publish tokens, `--//registry.npmjs.org/:_authToken=`, curl -H 'Authorization: Bearer ...', database connection strings, cloud CLI credentials, signing passwords. Warden would durably persist a plaintext credential archive with no stated ACL, no retention limit and no redaction, and would then be an attractive target itself. Redact against a secret-pattern list before writing, ACL the log to Administrators/SYSTEM, and cap retention.
- D16 offers 'a one-click revert' for LSA/UAC registry keys. Auto-reverting EnableLUA, RunAsPPL or LsaCfgFlags changes boot-time security posture and can lock a user out or break software they depend on; RunAsPPL in particular can prevent third-party security tools from loading. These must be presented as advisory with the exact before/after values and an explicit reboot warning, never applied autonomously, and the baseline must be captured before Warden's own installation touches anything.
- If Warden and the guardian process communicate over IPC, that channel is a privilege boundary: an elevated component that quarantines files and kills processes on request must not accept requests from a medium-integrity process. The spec never mentions the IPC mechanism or its ACL. A named pipe with a default DACL here converts any local code execution into arbitrary file destruction with SYSTEM rights.
- Warden's own behaviour profile — an unsigned self-built binary, running elevated from a highest-privileges logon task, enumerating the system handle table, duplicating handles, reading other processes' memory, subscribing to clipboard updates, and self-protecting against termination — is a close match for the malware it hunts. Microsoft Defender's ASR rule 'Block credential stealing from the Windows local security authority subsystem' will block the handle work against lsass, and behavioural monitoring may quarantine Warden itself. The build plan needs a Defender-interaction step: verify against ASR early, sign the binary, and document the exclusions the user would have to add — while noting that asking a user to exclude your security tool from Defender is precisely the pattern D17 exists to detect.

### Omissions
- The largest gap: the spec rules out ETW on the premise 'no ETW-kernel', but an elevated usermode process can start a real-time ETW session and consume manifest providers with nothing but P/Invoke to advapi32 (StartTraceW, EnableTraceEx2, OpenTraceW, ProcessTrace) and tdh.dll for decoding — no driver, no NuGet, no Sysmon. Microsoft-Windows-Kernel-Process gives lossless ProcessStart/ProcessStop/ImageLoad; the classic process events additionally carry the command line; Microsoft-Windows-DNS-Client gives per-PID DNS queries and answers; Microsoft-Windows-TCPIP gives per-PID connect events with no poll gap. That single addition fixes the three acknowledged structural holes at once — sub-second processes invisible to a 2s Toolhelp poll, sub-poll connections, and inferential DNS attribution — and would make roughly a dozen command-line detections go from near-zero recall to reliable. (Microsoft-Windows-Threat-Intelligence is genuinely off-limits without an anti-malware PPL signature; the ordinary manifest providers are not.) At minimum, evaluate and document why it was rejected.
- No revocation or review path for anything learned during the 7-day learning mode. Learning mode assumes a clean host; if the machine is already compromised, the resident implant is signed into the publisher allowlist, its beacon endpoints into the network baseline, its listener into the listener baseline, and its persistence into the ASEP baseline — permanently and invisibly. Add: a prerequisite Defender full scan, a reviewable list of everything the baseline absorbed, per-item revocation, and a rule that a HIGH-tier anchor is recorded (not acted on) during learning so the evidence exists retroactively.
- No uninstall, pause or panic path is specified for a tool that terminates processes autonomously. There must be a documented way to stop Warden that works when Warden is misbehaving, including a Safe Mode / boot-time disable, and a 'suspend all autonomous action for 4 hours' control the user can reach in one click from the tray.
- Score decay uses a 30-minute half-life with no stated clock source. Wall-clock time moves backwards across NTP corrections and jumps across sleep/hibernate, which would either instantly expire or indefinitely preserve every signal. Specify a monotonic source (Environment.TickCount64 / Stopwatch) and define what happens to in-flight scores and suspended processes across a sleep/resume cycle.
- Path handling never accounts for known-folder redirection. Downloads, Documents and Desktop are commonly redirected into OneDrive on Windows 11, so string-building from %USERPROFILE% misses the real Downloads folder for D21/D37 and misclassifies OneDrive-backed paths. Resolve every user location through SHGetKnownFolderPath, resolve reparse points, and note that OneDrive placeholder hydration generates file events that look like mass file creation.
- D34's ASEP list is missing several persistence locations that are actively used and cheap to watch: HKLM\SYSTEM\CurrentControlSet\Control\Lsa Notification/Security/Authentication Packages (LSA plugin persistence, directly relevant to the credential-theft theme), Winlogon\Notify, netsh helper DLLs (HKLM\SOFTWARE\Microsoft\Netsh), Active Setup\Installed Components, print monitors/processors, AppCompat shim databases installed via sdbinst, BITS jobs carrying a SetNotifyCmdLine, and HKCU\Software\Classes protocol/shell-open-command hijacks (the fodhelper/ms-settings family — fodhelper is listed as a LOLBin but its registry ASEP is not watched).
- The LOLBin set in D07 omits the interpreters this user actually has installed, which are strictly better LOLBins than half the list: node.exe -e, python.exe -c, wsl.exe / bash.exe (a complete execution environment invisible to every Windows-process detection here), deno, bun, and winget.exe. A stealer that runs `node -e` bypasses the entire command-line family. At the same time the list contains images that do not exist as executables ('wt.exe-as-proxy', 'DotNetDiagnosticClient'), which suggests it was not validated against the machine.
- Nothing describes what happens when Defender and Warden act on the same file concurrently. Defender quarantining a file Warden has open for hashing, or Warden moving a file Defender is mid-scan on, produces sharing violations and partial states. Define the interaction: check Defender's Operational log for a recent action on the same path before quarantining, and treat a Defender detection as authoritative rather than racing it.
- No integrity protection for the quarantine vault or its sidecar JSON. If the vault is restorable by any medium-integrity process, malware can simply restore itself; if the sidecar (original path, ACL, timestamps) is writable, restore becomes an arbitrary-file-write primitive running elevated. ACL the vault to SYSTEM/Administrators, and sign or HMAC the sidecar records.
- There is no shadow-copy or restore-point step before the first destructive action of an incident. For a tool whose stated primary risk is false positives, taking a VSS snapshot (or at minimum verifying System Protection is on) before the first quarantine of a session is cheap insurance and turns an irreversible mistake into a recoverable one.
- The 150MB working-set and 1%-of-one-core budget is not achievable as designed. A .NET 10 WPF process starts around 60-90MB before doing anything; add a signature cache, module lists for ~400 processes, and SystemExtendedHandleInformation snapshots (300k-800k entries on a machine running Chrome, Unreal and BlueStacks, at 40 bytes each, every 15 seconds) and both the memory ceiling and the GC pressure target are gone. Split the design: a headless worker holding the telemetry planes and the scoring loop, and a WPF dashboard launched on demand and torn down when closed. Allocate handle snapshots in unmanaged memory and read them through spans rather than materialising managed arrays.
- Per-process CPU sampling via Process.TotalProcessorTime (D24/D25) opens and holds a handle per process, allocates a Process object per PID per sample, and throws on exited or protected targets. On a 24-thread machine with hundreds of processes at a 5s cadence this is both the handle-leak risk the implementation notes warn about and a meaningful share of the CPU budget. One NtQuerySystemInformation(SystemProcessInformation) call returns CPU times, thread counts, image names and I/O counters for every process at once, and is already being paid for elsewhere.
- D36's clipboard mechanism has two unstated hazards. AddClipboardFormatListener is widely reported not to deliver WM_CLIPBOARDUPDATE to message-only (HWND_MESSAGE) windows — use a hidden top-level window and verify delivery in a probe. And GetClipboardOwner returns NULL whenever the setter used OpenClipboard(NULL) or a temp window that has since been destroyed, which is common, so writer attribution will frequently be absent — the swap rule must define its behaviour when the writer is unknown rather than defaulting to 'not the source process, therefore malicious'. Also note that opening the clipboard on every update can make other applications' SetClipboardData fail; retry with backoff and hold it for the minimum possible time.
- EventLogWatcher subscriptions are specified without bookmarks, so every Warden restart, service recycle or crash silently loses the events in the gap — exactly the window in which a compromise would act. Persist an EventBookmark per channel and resume from it, and handle the watcher's silent death when the Event Log service restarts (it does not raise an exception; it just stops delivering).
- No detection covers the highest-value modern persistence for a machine like this one: a malicious VS Code extension, an npm postinstall script, a Python package installed into a venv, a Blender addon, or a git hook. All execute as trusted developer tooling under a registered dev path, which the spec's own allowlists explicitly de-score to zero. That is a deliberate blind spot created by the FP tuning, and it should at minimum be named in the D48 coverage panel, with a Maintenance-side changelog of newly installed extensions/global packages/hooks rather than a scored runtime detection.
